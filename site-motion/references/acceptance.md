# 實作與驗收

## 實作順序

動工前先看版本控制狀態，專案可能有未提交變更，或別人正在同一專案工作，先協調再改。

風險低的先做，每一階段都能單獨上線：

1. 補 `prefers-reduced-motion` 與回饋（壓感、更新高亮、相對時間）
2. 同文件軟導覽才需要：先定好分析與廣告做法，見 [pitfalls.md](pitfalls.md)，再開軟導覽，不要反過來
3. 導覽做法與持久外框，修好所有頁面腳本的重跑問題
4. 原地展開、抽屜、合併物件
5. 共享元素轉場
6. 手勢、骨架、即時通知

每階段建置一次並提交。與專案既有決定衝突時，以既有決定為準並提出來。

## 驗收清單

**手感**（375px 實測）

- [ ] 主要路徑走一遍：切頁不白屏，外框不重繪，倒數不重置
- [ ] 上一頁、下一頁、重新整理、直接開內頁網址都正常
- [ ] 頁面專屬腳本切頁後仍可用
- [ ] 快速連點、轉場中再點不會壞
- [ ] 舊瀏覽器或不支援 View Transitions 時可用
- [ ] 流量來自社群時，內建瀏覽器走過主要路徑，系統返回手勢正常
- [ ] 中階 Android 上手勢與轉場不卡

**SEO**

- [ ] 前後比對 title、H1、canonical、robots、結構化資料無意外變動
- [ ] 關閉 JS 時主要內容仍在 HTML 內
- [ ] 所有內容仍可由 `<a href>` 走到
- [ ] 切頁後 title、canonical、`lang`、焦點與捲動位置正確
- [ ] 列表頁建置後的 HTML 大小沒有異常增加

**分析與廣告**

- [ ] 每次切頁只有一個 page_view，自訂參數正確，部署文件寫明 history 事件要開或要關
- [ ] 沒有真實 ID 時用假 ID 讀 `dataLayer` 驗證，驗完用無 ID 重建
- [ ] 廣告單元換頁後處理方式已確定，有廣告的頁面 CLS 正常
- [ ] 通知與抽屜不蓋住廣告

**品質**

- [ ] console 沒有錯誤
- [ ] 亮色、暗色（若有）、`prefers-reduced-motion` 都看過
- [ ] 鍵盤可操作，`aria-expanded` 正確
- [ ] 上線後用 PageSpeed Insights 比對改版前

## 交接範本

交給其他 agent 時用這個結構，對方只看得到訊息內容：

```markdown
使用者選定 <站名> 的 <版本> 動態方案，請實作。

**前提**：<不改版面／配色等限制>
**原型**：<連結或路徑>
**要落地的項目**：<編號清單，每項寫現象、做法、檔案>
**版面小合併**：<使用者同意的項目>
**不要動**：<已否決項、SEO 紅線>
**建議順序**：<順序>
**驗收**：<本檔的驗收清單>
**尚未確認**：<分析、廣告等前提>
```

對方回報完成後，先核對 commit 與檔案，再告訴使用者完成了什麼、哪些只是對方回報。
