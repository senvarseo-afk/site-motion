# 原型製作

目的是讓使用者用手機感受差異，不是做完整網站。判斷手感要親手滑、親手點。

## 內容

- **真實資料**：從專案資料抽一小段。假資料會讓人分心去看內容
- **現有外觀**：沿用專案的色彩、字體與元件比例，看起來就是他的網站
- **只做核心路徑**：首頁、一個內頁、一次回程，其他頁簡化
- **版本切換**：頂部放不屬於網站的切換列，用 `document.documentElement.dataset.v` 控制功能開關
- **操作提示**：頂部一行列出該試的動作
- **自動事件**：新資料通知這類事件約 6 秒後自動出現
- **廣告佔位**：有廣告的站，內文與底部錨定位置放真實尺寸的佔位，否則版本比較會失真
- **寬度**：360px 與 375px 都要成立

新站或空殼專案沒有外觀時，先用規劃文件的色票；連色票都沒有就用中性外觀和標明是範例的資料，並說明這階段只比手感。

原型是單頁模擬，手感接近但不等於正式行為：沒有真實網路延遲，也不能證明廣告或分析在軟導覽下正常。提案要講清楚。

## 技術

- 單一 HTML、原生 JS，不用建置工具，從 [assets/prototype-template.html](../assets/prototype-template.html) 改起
- 交付方式依環境而定：能發布託管頁面就發布，否則給本機 HTML 路徑或暫時網址。頁面含未公開資料時，提醒使用者確認誰看得到
- 手機寬度滿版，桌機置中顯示手機框
- `prefers-reduced-motion` 要關動效

## 驗證（交出去之前）

1. 環境有瀏覽器工具就用手機寬度實際點過每個互動，看 console 沒有錯誤
2. 用本機伺服器測試時，不要覆蓋專案既有的設定檔，測完移除暫時設定並停掉伺服器
3. 背景分頁或隱藏視窗會暫停動畫與畫面更新，空白或半透明元素可能是環境造成。先用 `document.getAnimations()` 確認 playState，不要直接當成 bug
4. 重點測試：展開後是否被收回、橫滑是否卡住、回程轉場是否找得到目標、窄欄是否換行

沒有互動式瀏覽器時，用 Playwright 這類 headless 工具跑過點擊流程。語法檢查或邏輯測試都不等於驗過手感，要在提案的「未驗證」明說。
